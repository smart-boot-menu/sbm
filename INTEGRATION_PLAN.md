# SBM 0.0.1 integration plan (Wave 3)

Deliver one offline dual-architecture USB image rebuilt from immutable committed source revisions and qualified on both `x86_64` OVMF and `AArch64` AAVMF. The candidate boots the real Rust menu under 250 ms (HVF), discovers boot targets, verifies the native UKI on **Manage Computer** selection without $O(N^2)$ FAT32 overhead, boots real dm-verity EROFS `sbm-core`, renders the live Iced management UI, launches GParted displaying both virtual fixture disks, and reboots cleanly back into the same menu to confirm the boot attempt.

All Wave 3 engineering agents operate from the dedicated `~/gh/smart-boot-menu/` workspace and must respect the 16 GiB physical RAM budget on the macOS host.

## 2. Wave 3 critical path (strictly ordered)

1. **Unblock CI & fix host resource manager first (Parallel: Agent 03 + Agent 01 formatting):**
   - **Agent 03 (`sbm-lab`):** Fix `sbm-lab#5` (shell `--owner-pid`, `read_qemu()` self-detection, `short_id()` collision, PID-reuse `SIGKILL`, `clean --stop`, `--detached` builders, `admit.lock` TOCTOU, reboot/start-time reaping, QEMU arg parsing, Linux budget/cliff, `Workload::Efi` vs Core UKI classification, standalone lookup). Fix `sbm-lab#3` (`accel.rs:196` `-cpu max` -> `cortex-a57` or `max,pauth-impdef=on` for AArch64 TCG) and `sbm-lab#4` (`run.rs:495-505` `forbid_markers` bug). Confirm `sbm-lab` hosted CI (`check`, `smoke`, `product`, `secure`) is 100% green.
   - **Agent 01 (`sbm-uefi`):** Immediately fix `cargo fmt` (`qemu.rs:107-110`) and standalone `sbm-lab` lookup so `sbm-uefi` CI returns to green while completing the `sbm-uefi#1` implementation.
2. **Fix UEFI startup latency + Spec 02/03 handoff & Core graphical boot blockers (Parallel: Agent 01 + Agent 02):**
   - **Agent 01 (`sbm-uefi#1`):** Implement lightweight startup discovery + single-open sequential streaming SHA-256 at launch (`1–4 MiB` buffer, `[profile.release.package.sha2] opt-level = 3`), fix all fail-open / `verified_signature` / `SECURITY_VIOLATION` masking / `read_any()` / `flush()` / UUIDv4 / 5 volatile EFI vars / `"local"` wildcard / double-reboot defects, expose **Manage Computer**, and publish rebuilt `sbm-{x86_64,aarch64}.efi` from a clean committed revision pinned to `sbm-common` `b3c77141`.
   - **Agent 02 (`sbm-core#1` & `#2`):** Apply all P0 graphical & handoff fixes (`/efi` dir in EROFS, `resolve_disk` canonicalize + ESP exemption in `protect_backing_device`, `start-session` auto-software-renderer + root-routed markers, `labwc_environ` via `sbm-ui`, `/var/lib/sbm/.config` ownership, `sbm-session.service` VT/PAM/wayland env, remove `BootCommand::Reboot` write, BLI/PARTUUID-bound ESP & 5 volatile EFI var reader, zero-fallback `boot-success.json` after live UI snapshot, fix `start-builder.sh`/`boot-smoke.sh` against `sbm-lab#5`), commit everything cleanly, rebuild both `arm64` and `x86-64` Core images from that exact clean commit (capturing `c7e9439` + all fixes), verify direct graphical boot (`SBM_UI_READY` + GParted + virtual disks) locally, and archive the exact build metadata (package list, UKI `.cmdline`, roothashes, PARTUUIDs, SHA-256s).
3. **Re-assemble immutable 0.0.1 candidate & run full integration qualification (Sequential: Agent 07 -> Agent 03):**
   - **Agent 07 (`install#1`):** Fix Spec 07 gaps (`artifacts` populated with both menus + both UKIs, `release-manifest.v1.json`, `build-receipt.json` package list & commands, `IMAGE_LAYOUT.md`, `ci.yml` toolchain, minor hardening), bump `sbm-common` to `b3c77141`, refresh `media/0.0.1.lock.toml` to the clean committed Agent 01 + Agent 02 inputs, prove byte-identical `check-reproducible.sh` on `media/0.0.1.lock.toml`, and deliver the candidate + receipt.
   - **Agent 03 (`sbm-lab#2`):** Implement `sbm-lab test --tier integration --image PATH` (USB removable overlay, decoy ESP + 1 GiB & 2 GiB disks, `virtio-gpu`, no `-no-reboot`, multi-stage QMP screenshots for picker / Iced UI / GParted selector / post-reboot picker, machine-checked assertions, plus all 4 negative scenarios) and pass both `x86_64` OVMF and `AArch64` AAVMF lanes on the **exact same unchanged raw image SHA-256**.
4. **Separate post-0.0.1 tracks (do not block 0.0.1 offline gate):**
   - Enrolled-key Secure Boot on real menu -> real Core (`sbm-lab#4`), remote signed command client (`sbm-uefi#2`), Core `wayvnc` relay (`sbm-server#1`), TPM quote verification (`sbm-server#2`), catalog ISO signatures & prod TUF (`sbm-catalog#1`), U-Boot real menu (`sbm-as#1`), `sbm-common#2` `StorageOp` migration, design tokens (`sbm#1`), `sbm-agent#1`, and website (`smart-boot-menu.github.io#1`).
