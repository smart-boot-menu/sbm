# Smart Boot Menu — Integration Plan, Dependencies & Ownership

**Last updated:** 2026-11-26  
**Scope:** Coordinates **Track A (Agent 18)**, **Track B (Agent 16)**, **SBM 0.0.1** (independently qualified per-arch offline recovery media), **SBM 0.0.2** (persistent internal SSD installation, firmware registration, uninstall & recovery), and **SBM 0.0.3** (cross-platform Media Creator & guided partition resizing).

All engineering agents operate from the dedicated `~/gh/smart-boot-menu/` workspace, follow centralized [`.github/AGENTS.md`](../.github/AGENTS.md) and [`ADR-010`](../docs/architecture-decisions/ADR-010-open-source-reuse-and-engineering-principles.md), and respect the 16 GiB physical RAM budget on the macOS host. **Never modify physical host disks, firmware `BootOrder`, or macOS `LocalPolicy`/SIP.**

## 2. Critical Path & Sequencing

### Phase 1 — Parallel Immediate Execution (Track A + Track B + Finish SBM 0.0.1)

1. **Track A — Native Interactive UI Preview (`Agent 18`, zero VM cost, runs immediately in parallel):**
   - Build interactive native host preview for `sbm-uefi` (real `sbm-gfx` + `sbm-boot` over simulated ESP/targets/clock/handoff) and `sbm-core` (real Iced `sbm-ui` over pluggable `SimulatedCoreBackend`), including simulated **Manage Computer** -> Core UI -> **Install SBM** wizard -> Reboot round-trip.
   - Coordinate shared simulator fixtures/scenarios with Agent 01 (`sbm-uefi`), Agent 02/13 (`sbm-core`), and Agent 07 (`install` `sbm-plan`).
2. **Track B — OSS Dev Infrastructure & Resource Optimization (`Agent 16`, runs in parallel):**
   - Land root `justfile` composing existing tools, configure Cargo 1.100 `build.build-dir` + `sccache`, enable `mkosi --incremental=yes` + `systemd-sysext` for Level 2 Core iteration, consolidate `sbm-lab` duplicate `gpt.rs`/`fatimg.rs` onto `sbm-media`, and (upon user approval to install `lima` + `krunkit`) benchmark Lima+`krunkit` vs QEMU HVF builder so custom builder scripts can be retired.
3. **Close Remaining SBM 0.0.1 Gates (Independent Per-Arch Qualification):**
   - **Merge & Unblock CI (`Agent 02/13` + `Agent 03`):** Reconcile and push `sbm-core` (`5031613` + `098921f`), fix `sbm-lab#5` resource manager defects, push `sbm-lab` `integration.rs` (`sbm-lab#2`), and verify green CI.
   - **UEFI Latency & Spec 03 Handoff (`Agent 01` — `sbm-uefi#1`):** Restore `< 250 ms` HVF startup via lightweight discovery + launch-time single-open streaming SHA-256 (`sha2` `opt-level = 3`), publish all 5 Spec 03 volatile EFI vars with empty load options, enforce strict `attempt_id` confirmation, and pin `sbm-common` `b3c77141`.
   - **Per-Arch Media Assembly (`Agent 07` — `install#1`):** Add primary single-arch profiles (`sbm-0.0.1-uefi-x86_64.raw[.zst]` and `sbm-0.0.1-uefi-aarch64.raw[.zst]`), keep `dualarch` as optional experimental, populate `ReleaseManifest.artifacts` + `release-manifest.v1.json` + optional `sbm-os-list.json`, and prove byte-identical `check-reproducible.sh` per arch.
   - **Independent Qualification (`Agent 03` — `sbm-lab#2`):** Run `sbm-lab test --tier integration --image <per-arch-raw>` independently for `aarch64` (HVF) and `x86_64` (native Linux KVM CI / local TCG) and archive evidence in `research/validation/evidence/`.

### Phase 2 — SBM 0.0.2 (Persistent Internal SSD Installation, Uninstall & Recovery)

1. **Shared Schema Alignment (`Agent 11` / `Agent 07`):** Merge [`sbm-common#2`](https://github.com/smart-boot-menu/sbm-common/issues/2) (`StorageOp::CreatePartition` `unique_guid`/`attributes` + `SetPartitionFlags`).
2. **Planner, Executor & CLI Subprocess Wrappers (`Agent 07` + `Agent 02`):** Implement Spec 04 §11a available-space-only internal install, non-destructive ESP coexistence / fallback dedicated SBM ESP, `sgdisk --backup`, `efibootmgr` registration, `\EFI\sbm\install-receipt.json`, clean **Uninstall**, and **Repair SBM Boot Registration**.
3. **Interactive UI Flow (`Agent 18` + `Agent 02`):** Build and iterate the **Install SBM / Uninstall / Repair Boot** screens inside Iced `sbm-ui` using Track A native preview first, then wire to real `sbm-cored` IPC.
4. **Tier 1 & Tier 2 Qualification (`Agent 07` + `Agent 03`):** Pass Tier 1 regular-file planner/executor suites and Tier 2 disposable multi-OS QCOW2 VM tests (Gates `0.2-1` through `0.2-7`).

### Phase 3 — SBM 0.0.3 (Cross-Platform Media Creator & Guided Partition Resizing)

1. **Media Creator Trial & Delivery (`Agent 07` + `Agent 16`):** Evaluate minimal Apache-2.0 branded `rpi-imager` build pointing to SBM's release feed across macOS/Windows/Linux before considering any custom Rust/Iced flasher (per `ADR-010` and `ADR-011`).
2. **Guided Partition Resizing (`Agent 07` + `Agent 02` + `Agent 18`):** Implement Spec 04 §11b allowlisted shrinking (`ext4`, clean non-hibernated `NTFS`, single-device `Btrfs`) with the Golden Rule of Safe Shrinking, visual partition bar in `sbm-ui`, hard-blocking of encrypted/unsafe partitions, and Tier 1 + Tier 2 populated-OS QCOW2 verification (Gates `0.3-1` through `0.3-5`).
