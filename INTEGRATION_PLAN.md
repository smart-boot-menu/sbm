# Smart Boot Menu — Integration Plan, Dependencies & Ownership

**Last updated:** 2026-11-26  
**Scope:** Coordinates **Track A (Agent 18 — primary UX studio)**, **Track B (Agent 16)**, **SBM 0.0.1** (independently qualified per-arch offline recovery media), **SBM 0.0.2** (persistent internal SSD installation incl. `< 1 MiB` `efi-only` upgradeable profile, firmware registration, uninstall & recovery), **SBM 0.0.3** (cross-platform **`SBM Manager`** MVP, guided partition resizing & initial signed `systemd-sysext` modularity), and **SBM 0.1** (standards-based on-demand network recovery, `ram-only` zero-SSD-touch mode, ephemeral revocable remote repair, full modularity & OS catalog; [`sbm#5`](https://github.com/smart-boot-menu/sbm/issues/5)).

All engineering agents operate from the dedicated `~/gh/smart-boot-menu/` workspace, follow centralized [`.github/AGENTS.md`](../.github/AGENTS.md), [`ADR-010`](../docs/architecture-decisions/ADR-010-open-source-reuse-and-engineering-principles.md), [`ADR-011`](../docs/architecture-decisions/ADR-011-native-preview-internal-install-and-media-creator.md), and [`ADR-012`](../docs/architecture-decisions/ADR-012-profiles-network-recovery-modularity-and-ux.md), and respect the 16 GiB physical RAM budget on the macOS host. **Never modify physical host disks, firmware `BootOrder`, or macOS `LocalPolicy`/SIP.**

## 2. Critical Path & Sequencing (Non-Disruptive Coordination With Agents 13, 16, 18)

### Phase 1 — Parallel Immediate Execution (Track A + Track B + Finish SBM 0.0.1)

1. **Track A — Native Interactive UI Preview & Primary UX Studio (`Agent 18`, [`sbm#3`](https://github.com/smart-boot-menu/sbm/issues/3), zero VM cost, continues uninterrupted):**
   - Run the actual `sbm-gfx`/`sbm-boot` UEFI renderer and actual Iced `sbm-ui` natively against simulated platform interfaces (targeting `< 1 s` startup and `< 5 s` warm UI iteration) as the **primary workbench for evaluating and refining SBM's first-principles November 2026 UX** (`ADR-012`).
   - Coordinate shared simulator fixtures/scenarios with Agent 01 (`sbm-uefi`), Agent 02/13 (`sbm-core`), and Agent 07 (`install` `sbm-plan`).
2. **Track B — OSS Dev Infrastructure & Resource Optimization (`Agent 16`, [`sbm#4`](https://github.com/smart-boot-menu/sbm/issues/4), continues uninterrupted):**
   - Complete root `justfile` workflows, Cargo `build.build-dir` + `sccache` + `nextest`, `mkosi --incremental=yes` + `systemd-sysext` Level 2 Core iteration, `sbm-lab` `gpt.rs`/`fatimg.rs` deduplication onto `sbm-media`, and Linux CI `os-autoinst` / U-Boot `sandbox` adoption.
3. **Close Remaining SBM 0.0.1 Gates (Independent Per-Arch Qualification):**
   - **Merge & Unblock CI (`Agent 02/13` + `Agent 03`):** Reconcile and push `sbm-core` (`5031613` + `098921f`), fix `sbm-lab#5` resource manager defects, push `sbm-lab` `integration.rs` (`sbm-lab#2`), and verify green CI.
   - **UEFI Latency & Spec 03 Handoff (`Agent 01` — `sbm-uefi#1`):** Restore `< 250 ms` HVF startup via lightweight discovery + launch-time single-open streaming SHA-256 (`sha2` `opt-level = 3`), publish all 5 Spec 03 volatile EFI vars with empty load options, enforce strict `attempt_id` confirmation, and pin `sbm-common` `b3c77141`.
   - **Per-Arch Media Assembly (`Agent 07` — `install#1`):** Add primary single-arch profiles (`sbm-0.0.1-uefi-x86_64.raw[.zst]` and `sbm-0.0.1-uefi-aarch64.raw[.zst]`), keep `dualarch` as optional experimental, populate `ReleaseManifest.artifacts` + `release-manifest.v1.json` + optional `sbm-os-list.json`, and prove byte-identical `check-reproducible.sh` per arch.
   - **Independent Qualification (`Agent 03` — `sbm-lab#2`):** Run `sbm-lab test --tier integration --image <per-arch-raw>` independently for `aarch64` (HVF) and `x86_64` (native Linux KVM CI / local TCG) and archive evidence in `research/validation/evidence/`.

### Phase 2 — SBM 0.0.2 (Persistent Internal SSD Installation, `< 1 MiB` `efi-only`, Uninstall & Recovery — [`install#2`](https://github.com/smart-boot-menu/install/issues/2))

1. **Shared Schema Alignment (`Agent 11` / `Agent 07`):** Merge [`sbm-common#2`](https://github.com/smart-boot-menu/sbm-common/issues/2) (`StorageOp::CreatePartition` `unique_guid`/`attributes` + `SetPartitionFlags`).
2. **Planner, Executor & CLI Subprocess Wrappers (`Agent 07` + `Agent 02`):** Implement Spec 03 §9a & Spec 04 §11a supporting both **`efi-only` (`< 1 MiB`, independently useful and upgradeable without reinstalling `sbm-uefi`)** and available-space-only **`offline-full`**, non-destructive ESP coexistence / fallback dedicated SBM ESP, `sgdisk --backup`, `efibootmgr` registration, `\EFI\sbm\install-receipt.json`, clean **Uninstall**, and **Repair SBM Boot Registration**.
3. **Interactive UI Flow (`Agent 18` + `Agent 02`):** Refine **Install SBM / Uninstall / Repair Boot** screens inside Iced `sbm-ui` using Track A native preview first, then wire to real `sbm-cored` IPC.
4. **Tier 1 & Tier 2 Qualification (`Agent 07` + `Agent 03`):** Pass Tier 1 regular-file planner/executor suites and Tier 2 disposable multi-OS QCOW2 VM tests (Gates `0.2-1` through `0.2-8`).

### Phase 3 — SBM 0.0.3 (Cross-Platform `SBM Manager` MVP, Guided Partition Resizing & Initial `systemd-sysext` Modularity — [`install#3`](https://github.com/smart-boot-menu/install/issues/3))

1. **`SBM Manager` Architecture Decision & MVP (`Agent 07` + `Agent 16` + `Agent 18`):** Empirically compare a minimal Apache-2.0 `rpi-imager` fork vs. a thin Rust/Iced `SBM Manager` reusing mature OS flashing backends (`udisks2`/DiskArbitration/Win32), then deliver cross-platform profile configuration, cache/module selection, USB flashing, and read-back verification (`ADR-011`, `ADR-012`).
2. **Guided Partition Resizing (`Agent 07` + `Agent 02` + `Agent 18`):** Implement Spec 04 §11b allowlisted shrinking (`ext4`, clean non-hibernated `NTFS`, single-device `Btrfs`) with the Golden Rule of Safe Shrinking, visual partition bar in `sbm-ui`, hard-blocking of encrypted/unsafe partitions, and Tier 1 + Tier 2 populated-OS QCOW2 verification.
3. **Initial Signed `systemd-sysext` Modularity (`Agent 02` + `Agent 16`):** Split optional heavy tools out of `sbm-core`'s base into signed `dm-verity` `.sysext.raw` DDIs (`mkosi Format=sysext`, `--image-policy='root=signed+absent:usr=signed+absent:=unused+absent'`) so compressed base converges toward `< 500 MiB` (`Spec 07 §17a`).

### Phase 4 — SBM 0.1 (On-Demand Network Recovery, Ephemeral Remote Repair, Full Modularity & OS Catalog — [`sbm#5`](https://github.com/smart-boot-menu/sbm/issues/5))

1. **Standards-Based Network Recovery (`Agent 01` + `Agent 02` + `Agent 07`):** UEFI HTTP(S) Boot fast path + signed minimal Linux Network-Bootstrap UKI + `dm-verity` `switch-root` (Ethernet + Wi-Fi, HTTP `Range` resume, `≤ 2 GiB` low-RAM guard, offline fallback), strict `ram-only` zero-SSD-touch execution, and opt-in `cached-usb`/`cached-ssd`.
2. **Ephemeral Revocable Remote Repair (`Agent 02` + `Agent 05` + `Agent 07`):** `SBM Manager` USB preparation with `EphemeralRecoveryGrant`, local active-session indicator + one-action kill switch, zero permanent credentials or unattended command hooks on USB (`Spec 06 §16a`).
3. **Full Modular Extension Lifecycle (`Agent 02` + `Agent 07`):** Complete `systemd-sysext`/`systemd-confext` + `systemd-sysupdate` download, cache, activate, deactivate, and remove flows (`Spec 07 §17a`), alongside `sbm-catalog`, optional `sbm-server`, and `sbm-agent`.
