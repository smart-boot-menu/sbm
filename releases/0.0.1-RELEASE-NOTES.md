## 1. What Is in SBM 0.0.1

SBM 0.0.1 delivers independently qualified, offline, architecture-specific bootable UEFI recovery USB images (`x86_64` and `aarch64`) that exercise the full real firmware-to-Linux recovery loop:

- **UEFI Boot Manager (`sbm-uefi@4bfb3ba` — Classic UI with Atkinson Hyperlegible Typography):**
  - Renders the **Classic UI** with bundled **Atkinson Hyperlegible Next & Mono** vector typography (`410,112 B` `aarch64` / `465,920 B` `x86_64`, well under the `< 1 MiB` target).
  - *Note:* Newer experimental hardware dashboards (`sbm-uefi@70a84c5..457c545`, behind `experimental-layouts`) are host-preview experiments only and are **not** included in SBM 0.0.1.
  - Cold-boot `menu_ready` latency (Tier 2 accelerated VM, `N = 10` on exact frozen images):
    - **`aarch64` (HVF):** `min 8.36 ms`, **`median 15.83 ms`**, `p95/max 17.69 ms` (`<< 250 ms`).
    - **`x86_64` (native Linux KVM, `AMD EPYC 7763`, run `46073194023`):** `min 36.19 ms`, **`median 38.63 ms`**, `p95/max 41.32 ms` (`<< 250 ms`).
  - Single-open 1 MiB streaming SHA-256 verification of the native Core UKI fail-closed before `LoadImage`/`StartImage`, publishing all 5 Spec 03 volatile EFI variables with empty load options and UUIDv4 `attempt_id`.
- **Immutable Verified Recovery OS (`sbm-core@960f11a`):**
  - Clean `SBM_BUILD_PROFILE=release` Fedora 45 (`7.3.4-300.fc45`) `dm-verity` EROFS root (`/dev/mapper/root`), strict 5-var Spec 03 BLI handoff verification, zero dev/smoke root hooks (`sbm-smoke.service` excluded from production EROFS).
  - Live `labwc` + Iced `sbm-ui` desktop with automatic `pixman + tiny-skia` software-rendering fallback (verified on both `virtio-gpu`/`virtio-vga` and `ramfb`/`VGA`).
  - Real **GParted** over XWayland with refcounted read-only protection (`BackingRoTracker` + `GpartedDiskLease`) on the boot recovery disk.
  - Clean **Reboot** returning to the UEFI picker and confirming the exact UUIDv4 attempt (`consecutive_failures = 0`, deleting `boot-success.json`).
  - Operates **100% offline** (zero network interface, account, or server required).

## 4. Graphical Image-Flashing Tools Evaluation & USB Installation Instructions

Per [ADR-010](../../docs/architecture-decisions/ADR-010-open-source-reuse-and-engineering-principles.md) and [`research/ecosystem/media-creator-evaluation.md`](https://github.com/smart-boot-menu/research/blob/main/ecosystem/media-creator-evaluation.md), SBM 0.0.1 reuses mature existing open-source graphical flashers (**do not build `SBM Manager` prematurely** — `SBM Manager` MVP is scoped to SBM 0.0.3):

| Tool | License | Platforms | Native `.raw.zst` | Read-Back Verify | Recommendation for SBM 0.0.1 |
|---|---|---|---|---|---|
| **USBImager** (`bztsrc/usbimager`) | `MIT` | macOS, Windows, Linux | **Yes** | **Yes** (checkbox) | **Recommended primary offline flasher.** Tiny (`< 192 KB`), zero telemetry/ads, writes `.raw.zst` directly to USB without manual decompression. |
| **Raspberry Pi Imager (`>= 2.0.11`)** | `Apache-2.0` | macOS, Windows, Linux | **Yes** (`>= 2.0.11` required for `.zst` fixes `#1661`/`#1605`) | **Yes** | **Recommended cross-platform GUI flasher.** Choose **Use custom** -> select `.raw.zst` (or `.raw`) -> skip OS customization (`No`) -> Write & Verify. |
| **GNOME Impression** | `GPL-3.0-only` | Linux | **Yes** | Checksum | **Recommended Linux native GUI.** Lightweight Rust/GTK4, streams `.raw.zst` directly. |
| **Rufus** | `GPL-3.0-or-later` | Windows | **Yes** (DD/raw mode) | SHA-256 | **Recommended Windows fallback.** Decompress `.raw.zst` if prompted, select `.raw` in DD Image mode. |
| **Fedora Media Writer** | `GPL-2.0-or-later` | macOS, Windows, Linux | `.raw` (decompress `.zst` first) | **Yes** | **Good cross-platform fallback** (also has a convenient **Restore USB drive** button to reclaim the USB stick afterward). |
| **balenaEtcher** | `Apache-2.0` | macOS, Windows, Linux | Check per version (`.raw` works) | **Yes** | **Not recommended as primary** (~150–190 MB Electron footprint and in-app promotional panels). |

### Flashing Steps (Requires a Dedicated `>= 2 GiB` Removable USB Drive — All Existing Data on the USB Drive Will Be Erased)

1. **Verify the downloaded image checksum first:**
   - macOS: `shasum -a 256 -c sbm-0.0.1-uefi-<arch>.raw.zst.sha256`
   - Linux: `sha256sum -c sbm-0.0.1-uefi-<arch>.raw.zst.sha256`
   - Windows (PowerShell): `(Get-FileHash sbm-0.0.1-uefi-x86_64.raw.zst -Algorithm SHA256).Hash`
2. **Flash using a graphical tool (recommended):**
   - **USBImager:** Select `sbm-0.0.1-uefi-<arch>.raw.zst`, check **Verify**, choose your removable USB drive (double-check size/name so you never pick an internal drive), and click **Write**.
   - **Raspberry Pi Imager (`>= 2.0.11`):** Device -> *No filtering*; OS -> *Use custom* -> select `sbm-0.0.1-uefi-<arch>.raw.zst`; Storage -> select your removable USB drive; when asked to apply OS customization settings, choose **No**; click **Write**.
3. **Optional CLI flashing (advanced users):**
   - Linux: `zstd -dc sbm-0.0.1-uefi-x86_64.raw.zst | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress`
   - macOS: `diskutil unmountDisk /dev/diskN && zstd -dc sbm-0.0.1-uefi-x86_64.raw.zst | sudo dd of=/dev/rdiskN bs=4m && diskutil eject /dev/diskN`
   - **Verify read-back** (first `1,120,927,744` bytes for `x86_64` or `1,097,859,072` bytes for `aarch64`) against the `.raw.sha256` digest before booting.

## 5. Known Limitations (SBM 0.0.1 Development / Preview)

1. **Physical Hardware Unverified:** Qualified exclusively on Tier 2 disposable VMs (AAVMF/HVF and OVMF/native Linux KVM). Real motherboard firmware, GOP, USB xHCI, trackpad, Wi-Fi, and low-RAM quirks on physical PCs (including `EXP-HW-HP01`) have not been verified yet.
2. **No Production Secure Boot Signing:** `production_secure_boot_claimed: false`. On physical Secure-Boot-enabled PCs, Secure Boot must be **temporarily disabled** in UEFI Setup (or development test keys enrolled) to boot SBM 0.0.1. Production Secure Boot (`rhboot/shim` + SBAT + NX + Microsoft UEFI CA 2023 / `shim-review`) is scoped to consumer-ready SBM 0.2+.
3. **No Production TUF / Sigstore Distribution Signatures:** `production_tuf_signed: false`. Verify downloads manually using the published SHA-256 digests.
4. **USB-Only Offline Recovery Media:** Internal SSD installation alongside existing OSes (`efi-only` and available-space `offline-full`, uninstall, boot recovery) is scoped to **SBM 0.0.2**; `SBM Manager`, guided partition resizing, and `< 500 MiB` modular `systemd-sysext` base are scoped to **SBM 0.0.3**; network recovery, `ram-only`, and ephemeral remote repair are scoped to **SBM 0.1**.
5. **64-bit UEFI Only:** 32-bit IA32 UEFI firmware and Legacy BIOS/CSM are not supported.
6. **Optional `sbm-os-list.json` Not Included in 0.0.1:** Use local file selection in USBImager or Raspberry Pi Imager (`Use custom`).
7. **Apple Silicon Physical Macs Not Supported in 0.0.1:** Generic `sbm-0.0.1-uefi-aarch64.raw.zst` targets standard UEFI ARM64 platforms (and QEMU/AAVMF); Apple Silicon Macs require `m1n1` + U-Boot + Apple DTB + 16 KiB-page `linux-asahi` (scoped to SBM 0.2).
